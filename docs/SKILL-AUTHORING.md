# 写一个 skill

Skill 就是一份写给模型看的操作步骤。用户装好之后，它的名字和一句话说明会出现在系统提示词的
`## 可用 skills` 段里；模型判断需要用到时，调 `read_skill("名字")` 把整篇正文读出来，再照步骤执行。

## 放在哪里

| 位置 | 用途 | 谁维护 |
|---|---|---|
| `<应用目录>/resources/skills/<skill-name>/SKILL.md` | 内置 skill，随应用发布 | 开发者 |
| `~/.desktop-agent/skills/<skill-name>/SKILL.md` | 用户自己的 skill（Windows 上是 `%USERPROFILE%\.desktop-agent\skills\`） | 用户 |

一个子目录 = 一个 skill。同名时**用户目录覆盖内置目录**，所以你可以用同名 skill 盖掉内置行为。

## SKILL.md 的格式

```markdown
---
name: my-skill
description: 一句话说明这个 skill 解决什么问题，模型据此判断何时调用
when_to_use: 可选字段——比 description 更精确的触发条件，正文中写步骤
---

# 我的 Skill

## 步骤
1. 第一步做什么（用动词开头）
2. 第二步做什么

## 注意事项
- ...
```

## frontmatter 字段

| 字段 | 必填 | 用途 |
|---|---|---|
| `name` | 是 | 唯一标识（和目录名保持一致），用于注入系统提示词 |
| `description` | 是 | 注入系统提示词用，模型据此判断何时调 `read_skill` |
| `when_to_use` | 否 | 更详细的触发条件，注入到 description 后面 |
| `version` | 否 | 字符串，界面显示用 |
| `author` | 否 | 字符串 |

缺 `name` 或 `description`、或者文件顶部没有 `---` 包裹的 frontmatter，这个 skill 会被**跳过**并在日志里记一条原因，不会影响其它 skill 加载。

## 写步骤的几条经验

- **动词开头**，一步一件事。模型是按顺序执行的，别把三件事写在一个编号里。
- **写清"怎么拿到输入"**：用哪个工具、参数是什么。含糊的步骤会让模型开始猜。
- **写清什么时候该停下来问用户**。步骤里没说的地方，模型只能自己发挥。
- **别写"参考 scripts/ 里的脚本"**：v1 里 skill 目录下的任何脚本文件都不会被任何代码路径引用或执行。要执行程序只能让模型调 `run_shell` 工具，那会走用户的审批弹窗。这是设计层面的承诺，不是注释。
- 正文尽量短。它每被读一次就占一次上下文，写长了挤的是用户自己的窗口。

## 改了之后什么时候生效

应用启动时扫一遍。改完 SKILL.md 后重启应用即可生效。
