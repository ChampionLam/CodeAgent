# 安装与部署排障

一句话：**装完 ≠ 装好**。没验证服务真的在跑、真的能访问，就不算完成。

## 步骤

1. **先核对环境**：操作系统与版本、CPU/内存/磁盘、端口占用（`ps`/`ss`/`df` 实测）、现有同类服务。先确认边界：装什么、装在哪、会不会动到已有东西。
2. **选安装方式并对齐用户约定**：包管理器优先；涉及 Docker 时遵守用户已有口径（基础镜像不含运行时、端口避开默认、compose 不裸 run、内网环境走内网镜像仓库）。不确定的约定先问，不要替用户定。
3. **看官方口径**：装不熟的东西先查官方安装文档/发行说明，版本兼容（运行时版本 × 依赖版本）对上再装。
4. **装的过程留痕**：每条命令的输出要看到结果；报错读全文再决定下一步，不原样重试超过两次。
5. **装完验证**，逐项做：
   - 进程在跑（ps / systemctl status / docker ps）
   - 端口在听且能连通（curl 健康检查，拿到真响应才算）
   - 一次端到端冒烟（访问一次页面/接口，看返回）
6. **写清恢复方式**：动过的配置、开的端口、落的数据目录列出来；给出卸载/回退办法。

## 出岔子的时候

- 权限不够：如实报"需要 sudo/管理员"，不要绕。
- 验证不通过但命令没报错：以验证结果为准，继续查（日志、防火墙、绑定地址），不宣称成功。
