# 运行与调试

一句话：**先看报错再动手**。没读完 traceback 就改代码，等于闭眼开锁。

## 步骤

1. **原样重现**。用 `run_shell` 按用户给的方式（或项目 README/脚本）先跑一遍，拿到完整输出。跑不起来说"跑不起来"并给原因，不要换个命令静默绕过。
2. **读完整个报错**。Traceback 从最后一行往上读：异常类型、消息、出错帧。stdout/stderr 都要看，别只看最后一行。
3. **说清环境**。跑之前先确认解释器/Node 版本、工作目录、需要的环境变量（缺的用 venv/uv 或先声明）。系统级问题用 `date`、`ps`、`df` 这类命令实测，不凭印象。
4. **二分定位**。不确定哪层坏的，从中间切一刀：输入到一半还对不对？依赖装没装对？端口占没占？一次只变一个变量。
5. **换路规则**：同一个命令连续失败两次就换思路（换工具、换入口、加打印、上调试器），不要第三次原样重试。
6. **修完必须重跑**，确认原来那个报错消失。顺带跑相关测试，确认没修出新问题。

## 出岔子的时候

- 交互式程序（REPL、CLI 问答）挂住：说明它需要交互输入，给出非交互替代（参数、脚本喂 stdin）再问用户要不要。
- 超时：给足超时时间再跑一次；仍超时就拆小任务或后台跑，别硬等。
- 修好了但不知道为什么：不算修好，继续查根因，否则下次还会挂。
