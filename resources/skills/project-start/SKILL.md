# 项目起步

一句话：**一次只问一件事，问完等他回话再往下**。别一口气抛四个问题，他不是在填表。

开场先招呼一句：**「欢迎使用项目会话。」** 然后问第一件事。问话用客气的说法（"请问…"），别用"行""先说这个"这种随口的口吻——面对用户，不能这么说话。

## 顺序

1. 先问：**「请问是新建项目，还是接入现有项目？」**

2. **新建项目** 的话：
   - 先问：**「请问项目名称是什么？」** 拿到名字就**把这个名字作为当前会话的标题**，之后别再用"新项目"这类占位名。
   - 再问："这个项目放在哪个目录？填个路径，我先记下来。"
   - 再问："这个项目想做成什么样？一句话说明一下。"

3. **接入现有项目** 的话，先问："现有代码在哪个目录？"
   - 拿到目录**先读一遍**再往下（文件结构、README、明显在用的框架）。没读过就别往下瞎问——答案就在代码里，问了显得你没看。
   - 这条不用问项目名称：标题用目录名就行。

4. 到这儿问最后一句："要不要先出一份改动方案给你过目？"（说清是 OpenSpec 那套：先出改动提案，他点头再动代码。）

5. 收尾：把聊出来的东西拢成一条开场任务，列成清单放进对话里——项目名称、项目目录、项目目标、方案方式，缺哪项就写"待定"。**然后停下，等他点头再动手。**别自己先改代码。

**技术栈这一步不在这里问**（用户 2026-10-09 口径：不着急、不是重点）。他要主动说了就记下来，没说就等真动代码的时候再确认。

## 出岔子的时候

- **他答的不是这个问题**（问新建还是接现有的，他回"我这台 git 老报错"）：别把他硬拉回剧本，跟着他那句话走，该看报错就看报错。等他聊回来，再接着问没问完的那一步。
- **答得含糊，接不上**（问目录，他说"就放我电脑里吧"）：说一句"这看着不像个路径，复制一个更稳"，然后**把同一个问题原样再问一遍**。别换个说法追问，也别自己挑一个目录替他定。
- **他不想答**：跳过去，标"待定"，往下走。流程是给事服务的，不是给他服务流程的。
- **他已经说过的事别重复问**（项目名称、目录如果前面提过就直接用，说一句"这块前面说过了"带过）。
