# 文档与报告生成

一句话：**先问给谁看、干什么用**，再动笔。给老板的一页摘要和给接手人的操作手册是两个东西。

## 步骤

1. **定读者与用途**（用户已说清就跳过）：这份东西给谁看、看完要做什么决定/照着做什么操作。拿不准就问一句，别猜。
2. **列骨架**。先给出章节目录让用户过目（快速任务可省，但心里要有）。章节按"读者会用什么顺序读"排，不按"我有什么素材"排。
3. **事实落地**。每个具体数字、日期、结论都来自工具刚查到的原文（`read_file` / `run_shell` / 网页抓取），标注出处；记忆里的内容只能当线索，查证过才写。
4. **正文写进文件**。用 `write_file` 落到工作区（如 `reports/20261012-xxx.md`），**不要把整篇灌进聊天窗口**；回复里只给路径 + 三五行要点。
5. **区分事实与判断**。报告里"现状/数据"与"我的建议"分开成不同章节，别混着写；没验证过的内容标"待确认"，不要伪装成结论。
6. **格式约定**：Markdown 默认；用户点名 Word/PDF 再用对应工具生成，文件名带日期。

## 出岔子的时候

- 素材不够：列明缺什么、去找谁/哪里拿，不要拿推测填空。
- 用户中途改口径：改完重写对应章节，并在文档开头注一版"修订说明"，不静默替换。
