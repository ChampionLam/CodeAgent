# 未知错误排查（兜底）

一句话：**先收集现场，再缩小范围，最后才问**。诊断的产出是一份事实清单，不是一句"我试试"。

## 步骤

1. **收全现场**，一样都不能少：
   - 完整报错原文（截图里的也要逐字读出来；只贴最后一行等于没有）
   - 什么时候开始的、之前改过什么（代码/配置/环境）
   - 环境：系统、版本、工作目录、相关进程与端口
   - 复现步骤：怎样能再触发一次
2. **复现一次**。能稳定复现的问题好查一半；复现不了就先记录"间歇性"，从日志/监控入手。
3. **二分收窄**。把问题空间切两半：是输入的问题还是处理的 问题？是这层还是下一层？每问一次"哪一半"，用一个实验回答。一次只变一个变量。
4. **查外部知识**：本地查不清就搜（错误原文 + 关键词），看官方 issue/文档；引用给出来处。
5. **形成假设清单**：列出仍可能的 2-3 个原因，各给一个能证实/证伪的实验，逐个跑。
6. **结论复述事实**：修好了就说清"根因是 X，我改了 Y，验证结果 Z"；没修好就交出**事实清单 + 已排除项 + 卡在哪一步 + 建议下一步**，再向用户/模型提问。**不要在没收集现场前就问人**——答案是问出来的没错，但先得知道问什么。

## 出岔子的时候

- 修好了但不知道为什么：回到第 5 步，找出真因，否则不算解决。
- 每个假设都被证伪：这本身就是结果，如实汇报"已知不是这些"，别硬编一个根因。
