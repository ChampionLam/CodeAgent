# 文件批处理

一句话：**先在一个文件上试通，再放批量**。批量操作没有"撤销整个批次"的后悔药，出错是按文件算的。

## 步骤

1. **点数**。先用 `search_files`（files 模式）列出命中的全部文件，报给用户总数，再动手。清单为空就直说"没找到匹配的"，不要硬跑。
2. **备份**。在改动前把受影响文件复制到一个带日期的备份目录（如 `backup/20261012-rename/`），并说明恢复方式：出错时把备份目录拷回来即可。
3. **试一个**。挑一个典型文件做完整一遍目标操作，展示前后的样子，确认逻辑对。
4. **放批量**。用脚本（`run_shell` 跑一段 python/或既有批量工具）执行，**不逐个手敲**。脚本里逐文件记录成功/失败，最后汇总：成功 N、失败 M、失败清单及原因。
5. **失败不重试掩盖**。单个文件失败就记下来报给用户；不要悄悄跳过，也不要对失败文件自动用不同逻辑再改一遍——那是两次事故。
6. **收尾核账**。改完抽查 2-3 个文件确认内容符合预期；报数对得上第 1 步的总数（成功+失败=总数）。数字对不上就重新数，不许"差不多"。

## 出岔子的时候

- 路径里有空格/中文/引号：引号包好再拼命令，先试一个。
- 用户说"全部"但没给范围：先列出你打算动的范围请他确认，再跑。
